Formato de recopilación de datos: una ficha por métrica y corrida

Los siete bloques se llenan automáticamente desde las evidencias (registro.json) y se replican en la hoja «Registro» del Excel.

1. Identificación

  • ID de métrica
  • Característica
  • Subcaracterística

2. Trazabilidad

  • Requisito (RF/RNF)
  • Caso o procedimiento
  • Script o herramienta

3. Condiciones

  • Corrida y versión
  • Fecha y URL
  • Entorno y navegador
  • Datos (SHA-256)

4. Medición

  • A y B (o valor)
  • Fórmula
  • Resultado X y unidad

5. Evaluación

  • Umbral y resultado esperado
  • Estado (aprobado, rechazado, pendiente)
  • Puntaje y categoría

6. Evidencia

  • Archivo JSON de la corrida
  • Capturas y trazas
  • Reporte HTML

7. Seguimiento

  • Responsable
  • Incidentes vinculados
  • Decisión y observaciones

Estados posibles

  • Aprobado: cumple el umbral
  • Rechazado: no lo cumple
  • Pendiente: sin medición
  • No aplicable: subcaracterística justificada

Clasificación de un fallo por su origen

Antes de corregir, cada fallo se reproduce y se clasifica. Así no se «arregla» el producto cuando el error estaba en la prueba, ni al revés.

Una prueba o medición no cumple lo esperado

Producto

El defecto se reproduce a mano en la versión publicada (cifras, interfaz, accesibilidad, rendimiento, código).
  • INC-01, 02, 11, 16, 18, 19, 21, 22 interfaz
  • INC-07, 09, 17, 20 código y datos
  • INC-08, 12 a 15 rendimiento
Acción: corregir el producto, publicar y volver a medir.

Script de prueba

El producto se comporta bien; el fallo está en el localizador, la aserción o la forma de registrar la medición.
  • INC-04 localizador ambiguo
  • INC-05 pérdida de filas
  • INC-06, INC-10 falsos positivos
Acción: corregir el script sin tocar el producto.

Infraestructura

El fallo depende del entorno: navegadores, red, hosting o herramientas de ejecución.
  • INC-03 navegadores no instalados
Acción: reparar el entorno y repetir la corrida con el mismo procedimiento.
