Data-collection format: one record per metric and run

The seven blocks are filled automatically from the evidence (registro.json) and mirrored in the Excel “Registro” sheet.

1. Identification

  • Metric ID
  • Characteristic
  • Sub-characteristic

2. Traceability

  • Requirement (RF/RNF)
  • Test case or procedure
  • Script or tool

3. Conditions

  • Run and version
  • Date and URL
  • Environment and browser
  • Data (SHA-256)

4. Measurement

  • A and B (or value)
  • Formula
  • Result X and unit

5. Evaluation

  • Threshold and expected result
  • Status (approved, rejected, pending)
  • Score and category

6. Evidence

  • Run JSON file
  • Screenshots and traces
  • HTML report

7. Follow-up

  • Owner
  • Linked incidents
  • Decision and notes

Possible statuses

  • Approved: meets the threshold
  • Rejected: does not meet it
  • Pending: not measured
  • Not applicable: justified sub-characteristic

Classifying a failure by its origin

Before fixing, every failure is reproduced and classified, so the product is not “fixed” when the error was in the test, or the other way round.

A test or measurement does not meet expectations

Product

The defect reproduces by hand on the published version (figures, UI, accessibility, performance, code).
  • INC-01, 02, 11, 16, 18, 19, 21, 22 interface
  • INC-07, 09, 17, 20 code and data
  • INC-08, 12 to 15 performance
Action: fix the product, publish and re-measure.

Test script

The product behaves correctly; the failure is in the locator, the assertion or how the measurement is recorded.
  • INC-04 ambiguous locator
  • INC-05 lost rows
  • INC-06, INC-10 false positives
Action: fix the script without touching the product.

Infrastructure

The failure depends on the environment: browsers, network, hosting or tooling.
  • INC-03 browsers not installed
Action: repair the environment and repeat the run with the same procedure.
